Agents are placed by the repository named in their sessions, and one can show before it has a pull request.

- **Name an agent's session for its pull request: `<owner>-<repo>-pr-<number>`.** An agent on pull request 98 of `acme/web` is named `acme-web-pr-98`, and may go on to say more (`acme-web-pr-98 fix tests`). An agent shows on a pull request only when its session is named this way. What the pull request's branch and title say plays no part.
- **The board gives you the name.** The drawer shows it for the selected pull request, and `c` copies it.
- **An agent with no pull request yet shows under its repository.** Name its session for the repository alone, as a word of its own: `acme-web`, or `acme-web reflow fix`. Yours, at its prompt, is counted among what you can get moving and comes first in what needs effort.
- **When you open the pull request, the ticker gives the new name.** It says what to rename the session to and selects the pull request, so `c` copies that name.
- **A name that leads nowhere is said.** Part 4 of the setup lists each agent whose name has `-pr-<number>` in it and that is on no pull request, with why. A name that fits two pull requests, or two repositories, puts the agent on neither, and the end of the ticker's line says so.
